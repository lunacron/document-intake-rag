# Document Intake RAG

Turns uploaded PDFs into searchable, citable knowledge and into structured records, with a human approving every record before it reaches the system of record.

Staff upload documents such as enrollment forms, transcripts and handbooks. They can then ask questions in plain English and get answers grounded in the documents, with citations. Forms can also be extracted into structured records. Each record goes to a review queue, and only an approved record is written to the legacy system.

All sample documents in `samples/` are fictitious. They are generated by `scripts/make_samples.py`.

## How it works

```
upload PDF  →  extract text  →  redact high-risk IDs  →  chunk  →  embed  →  Postgres + pgvector
question    →  embed  →  top-k chunks (filtered by role)  →  Claude  →  answer with citations
form        →  Claude tool use (JSON schema)  →  checks  →  review queue  →  approve  →  legacy system
```

- **Ingestion.** Text comes out of the PDF with `pypdf`. Presidio redacts high-risk identifiers (SSN, ITIN, credit card, IBAN, passport, driver's license) before anything is embedded or stored. The original file is saved unchanged. Chunks keep their page and section, so answers can cite them.
- **Search and answers.** A local embedding model (`snowflake-arctic-embed-s`) and pgvector find the closest chunks. Claude answers only from those excerpts, cites them like `[1]`, and says it can't find the answer when it isn't there.
- **Prompt-injection defense.** The answer prompt treats document excerpts as data, never as instructions, and Claude has no tools that can change anything when answering questions.
- **Access control.** Every chunk has an access level. The role (`viewer` or `registrar`) is applied as a filter inside the search query, so restricted content never reaches the model for a viewer.
- **Extraction.** Claude fills a Pydantic schema through forced tool use. The record is then validated, and every extracted value is checked against the form's text, so invented or altered values get flagged without asking the model to grade itself. Fields the model marks as uncertain are flagged too.
- **Human in the loop.** Extractions wait in a review queue. A registrar approves or rejects each one. Claude never writes to the legacy system.
- **Legacy bridge.** An idempotent adapter writes approved records to a mock legacy table. The application ID is the key, so sending a record twice updates it instead of duplicating it.
- **Cost tracking.** Each extraction stores the model, input and output tokens and its cost.

[docs/walkthrough.md](docs/walkthrough.md) follows one sample enrollment form through every step.

## API

| Endpoint | What it does |
|---|---|
| `POST /ingest` | Upload a PDF (registrar only) |
| `GET /documents` | List documents visible to the caller's role |
| `GET /search` | Semantic search, filtered by role |
| `POST /query` | Ask a question; get an answer with citations |
| `POST /extract/{doc_id}` | Extract a form into a structured record, which goes to the review queue |
| `GET /extractions`, `GET /extractions/{id}` | Review queue |
| `POST /extractions/{id}/approve`, `/reject` | Registrar decision; approve writes to the legacy system |
| `GET /legacy/students` | The mock legacy system's records |
| `GET /health` | Health check |

Examples:

```bash
# upload a form (registrar only)
curl -X POST localhost:8000/ingest -H "X-Role: registrar" \
  -F file=@samples/enrollment_sarah_wilson.pdf \
  -F label="Enrollment form - Sarah Wilson" -F subject_id=S1 -F subject_name="Sarah Elizabeth Wilson"

# ask a question
curl -X POST localhost:8000/query -H "X-Role: registrar" -H "Content-Type: application/json" \
  -d '{"question": "What allergies does Sarah have?"}'

# extract the form into the review queue, then approve it
curl -X POST localhost:8000/extract/1 -H "X-Role: registrar"
curl -X POST localhost:8000/extractions/1/approve -H "X-Role: registrar"
```

## Running it

```bash
cp .env.example .env          # add your ANTHROPIC_API_KEY
docker compose up --build     # Postgres + pgvector and the API on http://localhost:8000
python scripts/make_samples.py samples   # optional: regenerate the sample PDFs
```

Open http://localhost:8000/docs for the interactive API docs. Send the header `X-Role: registrar` to upload, extract and approve.

## Tests

38 unit tests cover chunking, matching a question to the right person, roles, redaction, page-text extraction and the extraction checks (grounding and schema). They need no database and no API key:

```bash
docker compose exec api python -m unittest discover -s tests -t . -v
```

## Evaluation

`evals/` scores each model-dependent step separately, so a failure points to where to look:

| Eval | Question it answers | Calls Claude? |
|---|---|---|
| `search` | Is the right chunk in the top 8? (embedding model, chunking, role filters) | No, free |
| `query` | Is the written answer right, and does it cite the right file? Failures are labeled `retrieval` (the right chunk never reached Claude) or `generation` (it did, and the answer is still wrong). | Yes, a few cents |
| `extract` | Do the extracted fields match the expected record for each form? | Yes, a few cents |

```bash
docker compose exec api python -m evals.run            # all three
docker compose exec api python -m evals.run search     # free
```

There are 22 question cases and 4 extraction cases. Expected values were copied from the sample PDFs by hand, never from model output.

## Limits of this version

- **The role comes from an `X-Role` header**, which anyone can set. That's fine for local development; a real deployment would read the role from a verified login token.
- **Scanned PDFs aren't supported.** Text extraction needs a text layer; scans would need OCR.
- **The legacy system is a mock table**, standing in for a real API, file drop or RPA integration.

## How it would deploy on AWS

The design keeps the move simple: storage sits behind a small interface (local disk becomes S3 by changing one class), all configuration comes from environment variables, Postgres with pgvector is used in both places, and the model and embedder sit behind single functions.

| Local | AWS |
|---|---|
| `./data/raw` | S3 with KMS encryption |
| Postgres container | RDS Postgres with pgvector |
| API container | ECS Fargate behind a load balancer |
| `X-Role` header | Cognito login tokens |
| `.env` | Secrets Manager |
| `docker logs` | CloudWatch |
| `pypdf` | add Textract for scanned documents |
| mock legacy table | the real legacy system over a private connection |

## Stack

Python 3.12, FastAPI, Pydantic, Postgres + pgvector, sentence-transformers, Presidio and spaCy, Anthropic SDK (Claude), Docker Compose.
